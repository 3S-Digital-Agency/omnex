# OMNEX™ — Politique de marque

> Version 1.0 — Statut : **proposée**.
>
> Cette politique régit l'utilisation du **nom, du logo et de l'identité
> visuelle OMNEX™**. Elle complète la matrice des licences
> ([`docs/licensing.md`](docs/licensing.md), ligne « Marque OMNEX™ ») : la
> marque n'est **pas** couverte par les licences de code (Apache 2.0, MIT,
> CC BY-SA) et reste la propriété de **3S Digital Agency** jusqu'à une
> éventuelle transition (§5).

---

## 1. Qu'est-ce que la marque OMNEX ?

La marque OMNEX™ comprend, sans s'y limiter :

- le **nom** « OMNEX » (et ses déclinaisons « OMNEX Cloud », « OMNEX Drive »,
  « OMNEX Sites », « OMNEX Cloud OS »…) ;
- le **logo** (nuage multicolore + wordmark) et ses variantes, favicon,
  icônes de marque ;
- le **slogan** « Cloud Infrastructure, Simplified » ;
- les **éléments d'identité** : palette de couleurs, typographie, style
  visuel associés à la marque ;
- le **domaine** omnex.cloud et les noms de domaine associés.

## 2. Ce que la licence de code autorise (et n'autorise pas)

La licence Apache 2.0 (ou MIT pour les SDK) autorise librement :
- copier, modifier, distribuer et vendre le **code** ;
- forker le projet et créer des œuvres dérivées du **code**.

Elle **n'autorise pas** automatiquement :
- l'usage du **nom** OMNEX pour désigner un produit ou service qui n'est pas
  le projet officiel ;
- l'usage du **logo** OMNEX dans un but commercial ou promotionnel sans
  autorisation ;
- toute présentation laissant croire qu'un fork ou un service tiers est
  officiel, affilié, parrainé ou approuvé par OMNEX / 3S Digital Agency.

## 3. Usage autorisé sans autorisation écrite

### 3.1 Usage « factuel » (toujours autorisé)

- Désigner le projet **officiel** : « OMNEX », « le projet OMNEX »,
  « OMNEX Cloud OS » pour parler du logiciel sous licence Apache.
- Mentionner la compatibilité ou l'intégration : « compatible avec OMNEX »,
  « un adaptateur pour OMNEX », **à condition** de ne pas laisser croire à un
  partenariat officiel.
- Citations et revues de presse, références académiques, comparaisons
  factuelles (tables de comparaison, benchmarks).
- Utiliser le logo officiel **tel quel** (sans modification) pour désigner
  le projet dans un contexte non commercial ou dans une liste de projets
  open source, avec un lien vers le dépôt officiel.

### 3.2 Attribution dans le code

- Le code redistribué (Apache 2.0) doit conserver les notices d'attribution
  et le NOTICE éventuel, conformément à la licence.
- Un fork doit indiquer clairement qu'il est un **fork** (« basé sur
  OMNEX ») et ne pas reprendre le logo comme logo principal de son propre
  produit.

## 4. Usage soumis à autorisation écrite

Tout usage commercial ou promotionnel de la marque nécessite une
**autorisation écrite** de 3S Digital Agency (ou de l'entité de gouvernance
à l'issue de la transition) :

- utiliser « OMNEX » dans le **nom d'un produit ou service** (y compris un
  SaaS hébergé qui n'est pas l'infrastructure opérée officielle) ;
- utiliser le **logo** sur un site web, une documentation commerciale, des
  goodies, des présentations, des publicités ;
- s'associer à la marque dans le cadre d'un **partenariat, d'une
  certification ou d'un programme de revendeurs** ;
- revendiquer un statut officiel (« Powered by OMNEX ») dans un produit
  commercial.

Demandes : `brand@omnex.cloud` — réponse sous 15 jours ouvrés, refus motivé
possible pour préserver la cohérence et la réputation de la marque.

## 5. Fork, dérivation et renommage

- **Fork autorisé** : n'importe qui peut forker le code (Apache 2.0) sans
  autorisation.
- **Renommage obligatoire** : un fork devenu un produit distinct doit
  choisir un **nom différent** et ne pas utiliser le logo OMNEX comme logo
  principal. Exemple : « ACME Cloud » à partir du code OMNEX est acceptable ;
  « OMNEX by ACME » sans autorisation ne l'est pas.
- **Mentions d'origine** : un fork doit conserver les mentions légales
  d'origine dans le code (obligation Apache 2.0) et peut indiquer « dérivé
  de OMNEX (Apache 2.0) ».
- **Pas d'ambigüité** : toute représentation qui créerait une confusion avec
  le projet officiel est interdite, y compris les variations orthographiques
  (OMNEX vs OMNeX, Omnix…) et les logos similaires.

## 6. L'infrastructure opérée (SaaS OMNEX Cloud)

L'hébergement « OMNEX Cloud » fourni par 3S Digital Agency est le seul
service habilité à utiliser la marque OMNEX pour désigner un service
**opéré**. Les services hébergés par des tiers (même basés sur le code
OMNEX) relèvent du §4 et doivent utiliser leur propre marque, sauf accord
de partenariat écrit.

## 7. Mise en œuvre & sanctions

- La politique est appliquée par l'entité de gouvernance (§2 de
  `GOVERNANCE.md`) et le mainteneur fondateur.
- En cas de violation : demande de retrait ou de correction sous 30 jours ;
  en l'absence de réponse, mise en demeure puis, le cas échéant, action en
  contrefaçon de marque.
- Les cas limites sont tranchés publiquement (issue de marque) pour créer
  une jurisprudence transparente.

## 8. Évolution de la politique

- Cette politique est révisable par le processus constitutionnel de
  `GOVERNANCE.md` (vote ⅔ des mainteneurs, discussion 14 jours).
- Toute modification est consignée dans le journal des versions.
